## 5. Lifecycle and Invariants

- Platform User states: `active`, `suspended`, `merged`, `anonymized`.
- `deleted` is not valid; PII removal uses irreversible anonymization.
- `merged` preserves the canonical user reference and cannot authenticate or create Membership.
- Identity Mapping states: `active`, `revoked`, `conflict`.
- Pending and Verified are credential-verification workflow states, not Mapping states.
- One verified Provider identity cannot have multiple active Platform User owners.
- Conflict never auto-merges or auto-relinks.

Historical correction uses Merge, Anonymize, Revoke or explicit conflict resolution; it never overwrites required history.

## 6. External Identity Security

- Raw Provider Subjects, Provider Tokens and credentials are prohibited from owned records, Stored Results, Audit and application logs.
- HMAC-SHA-256 input includes Provider, Issuer／Context and Subject using a versioned, unambiguous canonical encoding.
- Each mapping preserves `digest_key_version`.
- Resolution during key rotation checks the active key and permitted previous key versions before creating a Platform User.
- Rotation is a controlled, auditable, idempotent operation; a database Unique Constraint on one key version is insufficient.
- Secret creation and rotation execution require a Security Gate and are not authorized by this contract.

Security classification is `Restricted`; Identity metadata and Platform User references are confidential.

## 7. Permission, Idempotency and Audit

| Concern | Requirement |
| --- | --- |
| Permissions | Self-read for `platform_user:read_self`; mutations require verified self-link authority or Internal Administration |
| Idempotency | Identity Link scope includes operation, verified identity scope, actor and request fingerprint |
| Same request | Return safe Stored Result |
| Different fingerprint | Reject as Conflict; create no second mapping |
| Audit | Link, revoke, merge, anonymize and conflict decisions |
| PII | Minimize, mask and never persist raw Provider Subject |

## 8. Error, Retry and Observability

- Errors: Validation, Authentication, Permission, Scope, Conflict, Invalid State, Not Found and Temporary Dependency.
- Cross-tenant or restricted-resource responses do not disclose resource existence.
- Retry only temporary failures with the same Idempotency Key; permanent failure returns the Stored Result.
- Metrics cover resolution success, conflict rate, stale processing, merge and anonymization failures without Provider Subjects.

## 10. Testing and Compatibility

Required tests: UUIDv7 conformance, lifecycle transitions, same-identity uniqueness, conflict handling, merge chain, irreversible anonymization, key rotation continuity, raw-subject leakage, idempotency and security-boundary tests.

Breaking public-contract changes require a MAJOR version and Architecture Owner approval. Deprecation requires a documented replacement and migration window.
